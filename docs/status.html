What only a real terminal caught

The plan ended each visual task with run it and compare against the reference, and forbade claiming those steps from inspection. That instruction earned its place: four of the seven fixes below exist because the scripts were run on a real screen and the results measured. Every one of them passed bash -n, shellcheck, and the full suite first.

Flicker · c7dc1e6

draw() opened with tput clear, which emits ESC[H ESC[J — home, then wipe. The forty writes that repaint the frame are separate, so the terminal rendered the empty screen in between: 29 blanks, one per keypress, 33 ms each, visible ink dropping from ~593 px to ~30. It predated the rebrand entirely. Now the cursor homes, each line erases its own tail, and the erase-to-end runs after the frame is painted.

Width ceiling · b1f0499

Every full-width element — rules, bookends, both selection bars — had been 80 columns wide regardless of the terminal. One redirect did it: $(tput cols 2>/dev/null) makes ncurses read the window size off stderr, and the redirect throws that fd away, so it falls back to the static terminfo value. Found by measuring rather than looking: two screenshots at different window sizes both showed a rule of exactly 1759 px.

Truncated bars · 13afa3a · a14e915

Both selection bars stopped at the last character instead of reaching the edge. The tempting fix — stretch the background with CLR_EOL — is wrong here: screen and tmux advertise no bce, so ESC[K erases to the default background and truncates anyway. Installers run under tmux over SSH constantly, so both bars are painted with real spaces now.

Not a defect

A 256-colour check came back looking identical to truecolor — pixel-identical, in fact, zero channel delta. The tier was fine; QOL_COLOR_DEPTH=256 on its own line is a shell variable, not an environment one, so the child process never saw it. The failure mode is silence: the screen looks correct, just not at the depth you asked for.

What pass two turned up

Pass one's findings came from a screen. Pass two's came from tools and from reading the code for what it would do under a different environment — the conversion itself was mechanical, and every interesting thing was a consequence nobody had asked about.

A cache cannot be themed · 66744fb

netstatus.sh cached its rendered line. Painting it in place would have written ANSI into ~/.cache/qol/netstatus — and then a NO_COLOR=1 shell would replay the escapes, while one piped run would poison the cache uncoloured for every shell after it. The cache now holds the state token and the label; _ns_paint applies ink at print time, so the shell doing the printing decides. Migration needed no version field: the old format's line 2 was a rendered line, which can never match one of the five state tokens.

shellcheck is the gate, not bash -n

Generating shell from a Python heredoc double-escaped the line continuations, so printf '%s\n' "line one" \ ended in a literal \\ — a valid escaped-backslash argument — and the continued line silently became its own command. Every affected file still parsed clean. shellcheck -x flagged it as SC2288. bash -n only proves a file is a program, not the one you meant.

A helper can smuggle in a contract

ask_confirm returns yes whenever ASSUME_YES is set. Right for the two scripts that publish a --yes flag; wrong for kernel_update.sh, which publishes none — converting its rpi-update prompt would have let a stray environment variable flash unreleased firmware to a Pi that the prompt exists to protect. Four prompts kept their own read and took only the ASK chrome. The reasons are now in script-design.md, because "not ask_confirm, because…" is what separates a considered exception from not knowing the helper existed.

A clean exit is not a completion

A --dry-run, a declined prompt, and a nothing-to-do short-circuit all end at status 0, and all three used to fall through to a jade-ruled block announcing the work. uninstall_omz_p10k.sh now tracks which kind of nothing happened and says so. A completion badge over a run that changed nothing is a lie the reader takes as success.

Still open — accept the gap

gotime carries a copy of the palette that nothing validates. It is not in the generator's QOL_FILES, so --check never sees it and --write-qol cannot reach it. Closing that is not a one-line change: gotime names its inks C_* because some thirty printf call sites depend on those names, while the emitter writes QOL_*, so the generator would need a variable-prefix argument first. Verified by hand at the time it landed; verify by hand after any token change until someone does that work.

Pass two made it the only one. netstatus.sh needed the palette and none of the badge grammar, and the obvious move — hand-writing the five inks it reads — would have repeated this exact mistake. It carries the same marker-bounded generated region instead, under the same QOL_* names, so it costs three unread ink variables and a # shellcheck disable=SC2034 and buys full coverage. Six of the seven copies are now guarded by both the generator and test-theme-sync.sh.
