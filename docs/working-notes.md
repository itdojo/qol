# Working notes — qol

Durable repo knowledge. Point-in-time work state belongs in `docs/handoff.md`, not here.

## Constraints

- **Bash 3.2.** `install_zsh_starship.sh` and `gotime` run on macOS, which ships bash 3.2. No `declare -A`, no `${var^^}`, no `read -N`.
- **The milestone prefix is exactly 9 columns** — `▌`, space, 4-character badge, 3 spaces. Message text begins at column 10. Every badge pads to four (`ASK ` and `NEXT` alike), which is what removed the per-marker padding table the old emoji vocabulary needed.
- **The badge set is closed:** `STEP PASS INFO WARN STOP ASK NEXT`. Adding an eighth is a design-system change, not a script change — it belongs in the vault note first.
- **These public names must keep working:** `printline`, `style_text`, `format_font`, `log_title`, `fstring`, `log_info`, `log_step`, `log_ok`, `log_warn`, `log_err`, `check_status`. As of 2026-08-09 **no script in this repo calls the first five** — the rebrand reached every one of them — so they survive only as the published API someone else's script may source, plus `fstring`'s dispatch table and `tests/test-theme.sh`. Keep them working; do not call them.
- **Never name a shell function `complete`** — it is a bash builtin for programmable completion. The run-bookend helper is `log_complete` for exactly this reason, and `tests/test-theme.sh` asserts the builtin is still intact.

## Decisions

- **The palette's source of truth is the vault**, at `~/vaults/dojobrain/30-references/design-system/tokens/colors.css`, documented in `itdojo-terminal-design-system.md`. This repo holds copies, never originals. A second description of a color is a second thing to drift.
- **Color depth is never detected, only defaulted.** Truecolor is assumed; `QOL_COLOR_DEPTH=256|8|none` forces down. Detection would always guess low, because SSH strips `COLORTERM` (`sshd_config` ships `AcceptEnv LANG LC_*` and nothing else). A terminal that genuinely lacks 24-bit support approximates gracefully rather than printing garbage, so optimism costs less than detection.
- **The xterm-256 indices are perceptual picks, not nearest-cube matches**, and therefore cannot be computed. Nearest for violet `#BCB0E8` is 146, which reads gray beside the prose color. Three indices (violet 140, rule 60, selection 235) are chosen for separation on a projector over Euclidean accuracy.
- **The 8-color tier uses the bright set, not the dim one.** The dim six are unreadable on a near-black panel. This is the one place the brand's no-red rule yields to the medium — wine collapses onto bright red because there is nothing else.
- **The gutter bar prints at every tier including `none`**, so a log captured with `NO_COLOR=1` lines up with what was on screen and stays greppable as `grep -E '^. (WARN|STOP)'`.
- **`gotime` reads its layout from config, and was sanitized rather than moved to a private repo** (2026-08-09). It had hardcoded `~/courseware`, `~/projects`, and a pinned `~/vaults/dojobrain` window, which made it useless on anyone else's machine and published the author's directory layout in a public repo. Moving it to `~/fleet` was the alternative and was rejected twice over: fleet is machine provisioning rather than a user-tool home, and the personal surface turned out to be three variables and one window shape — cheaper to parameterize than to relocate. `GOTIME_ROOTS` and `GOTIME_PIN` now come from `~/.config/gotime/config`, and the tool got *more* useful in the process, since roots may now differ per machine. Note that this did not remove `~/vaults/dojobrain` from the public repo: seven other scripts cite the design-system note by absolute path, which is a separate question and probably fine.

## Ruled out

- **The emoji vocabulary** (`✅📦ℹ️⚠️❌`). It carried colors no script can override, `❌` renders a red the brand forbids, and its inconsistent advance widths are why the house style once had to document that "the uneven emoji padding is deliberate." The crest `⛩` survives in banners as brand furniture, not as a status marker.
- **Indenting subprocess output.** Piping `apt` or `curl` through `sed` to align it kills progress meters, swallows interactive sudo prompts, and buffers what should stream. Raw subprocess output stays flush left; only script-authored lines carry the gutter.
- **A per-line separator.** `printline` between every message meant nothing. A rule now marks a phase boundary, which is information.

## Gotchas

- **`configs/tmux.conf` runs two plugins by absolute path that nothing here installs — measured 2026-08-21 on a factory Mac.** The last two lines `run ~/.config/tmux/plugins/catppuccin/tmux/catppuccin.tmux` and `run '~/.config/tmux/plugins/tpm/tpm'`, and on a machine where neither is present each is `returned 127` at every tmux start. tpm does not save this: its `tpm` script binds `prefix + I` to an installer and returns, so loading it installs nothing. Invisible on any machine that has installed them by hand, which is every machine this config has ever run on until now. Found by `student-setup`'s `verify` on a fresh MacBook (`~/projects/student-setup/docs/working-notes.md`, 2026-08-21). **Change made here:** catppuccin is now declared alongside the other five as `set -g @plugin 'catppuccin/tmux'`, so `prefix + I` keeps it current — that is a declaration, not an install. **How to apply:** anything consuming this config still has to put tpm and catppuccin on disk itself; `student-setup`'s `editors` Module clones both before writing the file. A standalone qol user runs the two clones by hand, or the `run` lines want an `if-shell` existence guard so a bare machine gets a working tmux instead of two errors.

- **`_term_cols` needs both `2>/dev/null` *before* `</dev/tty` and a trailing `|| true`, and neither is style** (2026-08-20). With no controlling terminal — cron, CI, an agent, `ssh host cmd` — opening `/dev/tty` fails. Bash applies redirections left to right and reports a failed one on **its own** stderr, so the old `</dev/tty 2>/dev/null` printed `/dev/tty: Device not configured` past a suppression not yet in effect; the reorder silences that. **The reorder is not the fix.** The pipeline still exits non-zero, and a script running under `set -E` inherits its ERR trap into the command substitution and dies right there, at its opening banner, before doing anything. **Every script in this repo sets `-eo pipefail` and therefore only printed the message** — which is why this looked cosmetic for a week — but student-setup's `scripts/bootstrap.sh` sets `-Eeo` and reported `Failed at line 239` and stopped. One letter is the difference between noise and a script that cannot run unattended. `|| true` makes the fallback to 80 a fallback rather than a fatality; with a real terminal nothing changes, which `tests/test-term-width.sh` proves in the direction a no-tty test cannot see. Fixed in `linux/base_functions.sh` and byte-copied to all five embedding scripts here, plus student-setup's `scripts/vm.sh`, `scripts/bootstrap.sh` and its two vendored copies under `src/student_setup/payload/qol/`.
- **student-setup vendors two of this repo's scripts and no test on either side holds them together** (2026-08-20). `install_nano.sh` and `install_zsh_starship.sh` are copied into `~/projects/student-setup/src/student_setup/payload/qol/`. `tests/test-theme-sync.sh` here and `tests/test_theme_sync.py` there both cover the *theme block* in those files, so a block change cannot drift — but the rest of either script can, silently. **How to apply:** when changing a qol script that student-setup vendors, re-copy it there in the same pass.

- **Unused color variables trip shellcheck SC2034.** This has bitten twice — `QOL_SEL` in `base_functions.sh` (commit `c680f18`) and both `C_DIM` and `C_STEEL` in `gotime`. The rule that settled it: an SGR *attribute* with no reader gets deleted, a *token ink* with no reader gets a `# shellcheck disable=SC2034` and a comment saying why. `C_DIM` was deleted — the design retired dim-on-dim in favor of `C_META`, so nothing will want it back. `C_STEEL` was kept and suppressed, because dropping a token from a palette copy makes it a worse copy, and `gotime` emits no INFO line only because it states and asks rather than narrating.
- **The `gotime` menu frame's rules are gray, not jade** — `hr()` correctly uses `C_RULE`. Task 7 step 8 of the plan says to expect "jade rules" and is wrong; the rendered reference's Interactive pane draws all three `━` lines in `--terminal-rule`, and the reference is what step 8 tells you to compare against. Jade rules are for *run bookends* (`banner`, `log_complete` in `base_functions.sh`), where the point is finding a run's edges when scrolling back. A TUI on the alternate screen has no scrollback, so the rationale does not carry.
- **A cache that stores rendered text cannot be themed** (2026-08-09). `netstatus.sh` cached its finished output line, so painting `_ns_render` would have written ANSI into `~/.cache/qol/netstatus` — and then a `NO_COLOR=1` shell would replay the escapes, while one piped run would poison the cache uncolored for every shell after it. The cache now holds the *state* (`online|portal|nodns|offline|none`) and the interface label on separate lines, and `_ns_paint` applies ink at print time. Migration needed no version field: the old format's line 2 was a rendered line, which can never match one of the five state tokens, so `_ns_cache_read` rejects it and re-probes. Generalize the rule — **cache the decision, not the rendering**; anything a caller's environment can change belongs on the print path.
- **`netstatus.sh` embeds the generated ink block, not a fourth hand-written palette** (2026-08-09). It needs the colors and none of the badge grammar, and the obvious move — hand-writing five inks — would have repeated gotime's mistake below. Instead it carries the same marker-bounded region the theme copies do, under the same `QOL_*` names, so `--check` and `--write-qol` reach it and `tests/test-theme-sync.sh` proves it matches. The cost is nine ink variables where six are read, suppressed with `# shellcheck disable=SC2034`. That is the standing rule: **a token ink with no reader is suppressed, not deleted** — dropping a color from a palette copy makes it a worse copy.
- **`ASSUME_YES` is a contract, not a convenience, and `ask_confirm` opts a script into it silently** (2026-08-09). `ask_confirm` returns yes whenever `ASSUME_YES` is set. That is right for `install_nano.sh` and `uninstall_omz_p10k.sh`, which both document a `--yes` flag. It is wrong for `linux/kernel_update.sh`, which has no flags: converting its `rpi-update` prompt to `ask_confirm` would have let a stray environment variable flash unreleased firmware to a Pi that the prompt exists specifically to protect. Before swapping a hand-rolled prompt for the helper, check whether the script actually publishes `--yes`. Where it does not, borrow the chrome and keep the `read` — `script-design.md` lists all four reasons an exception is legitimate.
- **`bash -n` does not catch a broken line continuation, and `shellcheck` does** (2026-08-09). Generating shell from a Python heredoc double-escaped the continuations, so `printf '%s\n' "line one" \` ended in a literal `\\` — a valid escaped-backslash argument — and the second line silently became its own command. Every affected script still parsed clean. `shellcheck -x` flagged it as SC2288 ("interpreted as a command name ending with '.'"). Prefer the Edit tool over generated shell for anything with continuations, and treat `shellcheck` as the real gate; `bash -n` only proves the file is *a* program, not the one you meant.
- **`gotime` carries a third copy of the palette that nothing checks, and that is a decision, not an oversight** (2026-08-08). The vault's `build-design-tokens.py` knows only `linux/base_functions.sh` and `install_zsh_starship.sh` in its `QOL_FILES` list, so `--check` never sees `gotime` and `--write-qol` cannot reach it. Its hand-written `case` block was verified against `tokens/colors.css` when it landed — all nine truecolor triplets and all nine 256 indices — and it will drift silently from here. Wiring it up is not a one-line change: `gotime` names its inks `C_*` because ~30 `printf` call sites depend on those names, while the emitter writes `QOL_*`, so the generator would need a variable-prefix argument first. Verify by hand after any token change until someone does that work.
- **Never clear the screen at the top of a TUI redraw.** `tput clear` emits `ESC[H ESC[J` — home, then erase to end of screen — so the terminal sits blank for the ~40 separate writes that repaint it. On `gotime`'s 30-item menu that measured 33 ms of visibly blank screen per keypress, ink dropping from ~593 px to ~30, which is the flicker (fixed 2026-08-08; `tests/test-gotime-draw.sh` guards it). Home the cursor, overwrite each line in place, give every line its own `CLR_EOL`, and erase to end of screen only *after* the frame is painted. Position is everything: `ESC[J` right after `ESC[H` wipes the screen, while the same `ESC[J` at the foot of a drawn frame only drops the tail below it. The per-line `CLR_EOL` is load-bearing, not cosmetic — the selected row's `SEL_BG` runs to the right edge, so an unselected row that does not erase its own tail inherits that highlight.
- **Never put `2>/dev/null` on a `tput` you are capturing.** `cols="$(tput cols 2>/dev/null)"` reports the terminfo default of 80 no matter how wide the terminal is. ncurses reads the window size off whichever of stdout/stderr is a terminal; command substitution takes stdout, and the redirect throws stderr away, so it falls back to the static capability. `$(tput cols)` without the redirect answers correctly — the redirect *is* the bug. This pinned **every full-width element in the design system** to 80 columns for the life of the rebrand: `printline`, `banner`, `log_complete`, `log_phase`, `gotime`'s `hr`, and `ask_choice`'s selection bar (fixed 2026-08-08; `tests/test-term-width.sh` forces a 137-column pty and guards all of them). Both `_term_cols` and `gotime`'s `term_cols` now ask `stty size </dev/tty`, which no amount of nesting can hide, with `COLUMNS` as an explicit override and 80 as the floor. Reject a non-positive `COLUMNS` as well as a non-numeric one — this harness exports `COLUMNS=0`.
- **The symptom hid in plain sight for the whole rebrand.** Two `gotime` screenshots taken at different window sizes both showed a rule of exactly 1759 px — an identical absolute width at two different window widths, which is what a hard-coded column count looks like. Nothing looks broken at a glance; the chrome is simply narrower than the window. Measure a rule against the window before believing it fits.
- **A selection bar is padded with spaces, never stretched with `CLR_EOL`.** `ESC[K` only paints the current background across the rest of the line on terminals with the `bce` capability. `xterm-256color`, `ghostty` and `linux` have it; **`screen`, `screen-256color` and `tmux-256color` do not**, and there `ESC[K` erases to the *default* background, cutting the bar off exactly where the text ended. `ask_choice` is called by installers, which routinely run under tmux over SSH, so `_ask_choice_draw` pads every row out to `_term_cols` instead (fixed 2026-08-08; `tests/test-theme.sh` asserts both the selected and unselected row equal the terminal width). Padding the *unselected* rows is half the fix — that is what paints over the bar as it moves away. Measure the pad against a template with the same leading width as the row actually prints: three columns, `" ❯ "` or three spaces, not four.
- **`gotime`'s bar is padded the same way** (fixed 2026-08-08, same rule as `_ask_choice_draw`). Its *unselected* rows keep `CLR_EOL`, which is correct and portable there: erasing to the default background is exactly what clearing the bar off a row needs, `bce` or not. Only a bar being *painted* needs real spaces.
- **Cache the width per frame, do not look it up per element.** `term_cols` forks `stty`, and a `gotime` frame wants it four or five times — three rules plus the selected row. `draw()` sets a `COLS` global once per frame and `hr`/`render_row` read `${COLS:-$(term_cols)}`, so they still work if ever called outside a draw. Measured 5 calls per frame before, 1 after. Re-read it every frame rather than once at startup, or a window resize never takes effect.
- **Cursor control is not color.** `CLR_EOL`, `CUR_HOME`, and `CLR_EOS` are gated on `[[ -t 1 ]]` alone, never on `NO_COLOR`. A redraw still has to erase what it overwrites when the user has asked for no color; bundling them with the ink was what made the old `else` branch blank `CLR_EOL` and would have left highlight residue under `NO_COLOR=1`.
- **`QOL_COLOR_DEPTH` must be exported or prefixed, and the failure mode is silence.** A bare `QOL_COLOR_DEPTH=256` on its own line is a shell variable, not an environment variable, so `gotime` — a child process, and via `~/.zshrc`'s `alias gotime=...` still a child — never sees it and quietly renders truecolor. The screen looks *fine*, just not at the tier you asked for, so it reads as "the 256 tier is broken" rather than "the variable never arrived." Use `QOL_COLOR_DEPTH=256 gotime` on one line, or `export` it first. Two screenshots taken this way on 2026-08-08 came back pixel-identical, zero channel delta.
- **The repo-wide emoji grep now nearly passes, and the two survivors are deliberate** (updated 2026-08-09). The rebrand reached every remaining script, so `grep -rn '✅|📦|ℹ️|⚠️|❌'` over the shell scripts is clean *except* for `netstatus.sh`, whose `🛜 ✅ ❌ 🔒 🔌` are its product output rather than log badges — it prints a one-line readout at shell startup, and the nine-column badge grammar would destroy it — and the docs under `docs/`, which quote the retired vocabulary on purpose. Scope the check to exclude those two and it is silent. The superseded note below explains why it used to be unsatisfiable.
- **A repo-wide emoji grep will always fail, and that is correct** (superseded 2026-08-09 by the entry above; kept because it records why the plan's final verification step could not be met as written). The terminal-design-system plan's final verification runs `! grep -rn '✅|📦|ℹ️|⚠️|❌' --include='*.sh' --include='gotime' --include='*.md' .` and expects silence. It can never be silent: the same plan's Out of scope list keeps nine scripts on the back-compat helpers, `install_nano.sh` and `macos/install-nerd-fonts.sh` define their own emoji `log_*` wrappers, `netstatus.sh`'s `🛜 ✅ ❌` are its product output rather than log badges, and the docs under `docs/` quote the retired vocabulary on purpose. Scope the check to the five files the rebrand actually converted — `gotime`, `linux/base_functions.sh`, `install_zsh_starship.sh`, `linux/docker_install.sh`, `script-design.md` — which are clean.
- **`--write-qol` reaches only marker-bounded regions.** The vault rewrites the text between `# ‒‒ generated by dojobrain …` and `# ‒‒ end generated block`, and reports rather than guesses when a file lacks those markers. A file without them is invisible to the writer.
- **The two theme-block copies must stay byte-identical.** `install_zsh_starship.sh` embeds a copy because it must run on macOS where `linux/base_functions.sh` is unavailable. `tests/test-theme-sync.sh` is the only thing keeping that copy honest — run it after touching either file.
- **The vault never runs git here.** A `--write-qol` run lands uncommitted on purpose; committing in this repo is always a human act.
