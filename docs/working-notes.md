# Working notes — qol

Durable repo knowledge. Point-in-time work state belongs in `docs/handoff.md`, not here.

## Constraints

- **Bash 3.2.** `install_zsh_starship.sh` runs on macOS, which ships bash 3.2. No `declare -A`, no `${var^^}`, no `read -N`.
- **The milestone prefix is exactly 9 columns** — `▌`, space, 4-character badge, 3 spaces. Message text begins at column 10. Every badge pads to four (`ASK ` and `NEXT` alike), which is what removed the per-marker padding table the old emoji vocabulary needed.
- **The badge set is closed:** `STEP PASS INFO WARN STOP ASK NEXT`. Adding an eighth is a design-system change, not a script change — it belongs in the vault note first.
- **These public names must keep working:** `printline`, `style_text`, `format_font`, `log_title`, `fstring`, `log_info`, `log_step`, `log_ok`, `log_warn`, `log_err`, `check_status`. As of 2026-08-09 **no script in this repo calls the first five** — the rebrand reached every one of them — so they survive only as the published API someone else's script may source, plus `fstring`'s dispatch table and `tests/test-theme.sh`. Keep them working; do not call them.
- **Never name a shell function `complete`** — it is a bash builtin for programmable completion. The run-bookend helper is `log_complete` for exactly this reason, and `tests/test-theme.sh` asserts the builtin is still intact.

## Decisions

- **The generated-block marker no longer names the vault** (2026-09-09). `# ‒‒ generated by dojobrain scripts/build-design-tokens.py --emit-bash` became `# ‒‒ generated by build-design-tokens.py --emit-bash` in all seven copies, in `tests/test-theme-sync.sh`'s `extract_ink` range, and in `script-design.md`. Three of those seven are vendored into student-setup and published in a public take-home release, so the vault's *name* left the machine on every build. The marker is defined once, as `QOL_START` in the vault's `scripts/build-design-tokens.py`, and it is both what `--emit-bash` writes and what `--write-qol` searches for — so the rename could not go through a re-emit (the writer would no longer find the old region) and went through a one-time replace across all three repos instead. `--check` is clean and `test-theme-sync.sh` is 6/6. The historical plan under `docs/superpowers/plans/` keeps the old spelling on purpose: it records what was true when it was written.

- **Two scripts stopped citing the design-system note by absolute vault path** (2026-09-09). `install_nano.sh:43` and `netstatus.sh:52` now name the IT Dojo terminal design system and point at `script-design.md` in this repo, which names the vault note once and is the right place for it. The two were picked out of the nine because student-setup vendors exactly those two files byte-exact and publishes them in a public take-home release; that repo's release guard now refuses any build carrying an author vault path, so a re-sync cannot quietly restore these lines. The other six citations are unchanged — `install_zsh.sh`, `linux/base_functions.sh`, `linux/nm-connection-maker.sh`, `macos/install-nerd-fonts.sh`, `shell-login-settings.sh`, `uninstall_omz_p10k.sh` — because they ship to nobody, and the earlier ruling that this is "probably fine" still stands for them. `script-design.md` keeps its citation on purpose: it is the one place the path belongs.

- **The palette's source of truth is the vault**, in its design-system `tokens/colors.css`, documented in `itdojo-terminal-design-system.md`. This repo holds copies, never originals. A second description of a color is a second thing to drift.
- **Color depth is never detected, only defaulted.** Truecolor is assumed; `QOL_COLOR_DEPTH=256|8|none` forces down. Detection would always guess low, because SSH strips `COLORTERM` (`sshd_config` ships `AcceptEnv LANG LC_*` and nothing else). A terminal that genuinely lacks 24-bit support approximates gracefully rather than printing garbage, so optimism costs less than detection.
- **The xterm-256 indices are perceptual picks, not nearest-cube matches**, and therefore cannot be computed. Nearest for violet `#BCB0E8` is 146, which reads gray beside the prose color. Three indices (violet 140, rule 60, selection 235) are chosen for separation on a projector over Euclidean accuracy.
- **The 8-color tier uses the bright set, not the dim one.** The dim six are unreadable on a near-black panel. This is the one place the brand's no-red rule yields to the medium — wine collapses onto bright red because there is nothing else.
- **The gutter bar prints at every tier including `none`**, so a log captured with `NO_COLOR=1` lines up with what was on screen and stays greppable as `grep -E '^. (WARN|STOP)'`.
- **`gotime` is decommissioned** (2026-10-17). The owner no longer used it. The script, its two tests, `configs/gotime.conf.example`, the macOS alias and the README row went; git history keeps the tool. With it went the one hand-written palette copy the generator could not reach, so every palette copy in this repo is now checked. The theme block's "sharing gotime's chrome" comment stays: it is byte-synced across about fifteen files in several repos, and it records lineage rather than a live dependency.
- **Ubuntu's renamed binaries are resolved at runtime, not hardcoded.** `bat` ships as `batcat` there and `fd-find` as `fdfind`, both to avoid clashing with existing Debian packages, so `alias bat="bat --style=full"` pointed at nothing on Ubuntu and took the `cat` alias down with it. The alias block now picks the real binary with `command -v` first. This matters more than it looks: the AI-course classroom seats fetch this file verbatim over HTTP and the students' first impression of the shell is `cat`. Note `_have` is `unfunction`'d partway down the file, so the alias section cannot use it.
- **The guarded macOS branches stay even though the classroom seats are Linux.** `pbcopy`, the Homebrew fzf paths and the `uname == Darwin` check each sit behind an existence test and cost a Linux shell nothing. Week 2 of the AI course moves students onto MacBooks reading this same file, so stripping them would break the machines the class ends on. Corrected rather than removed, 2026-09-11.

- **Anything this file echoes at top level lands inside a caller's `$( )`.** The fzf trainer hints are now guarded on `[[ -t 1 ]]`, and the guard has to be that and not `[[ -o interactive ]]`: zsh sources `.zshrc` only for interactive shells, so the interactive test is always true here and guards nothing, while `zsh -ilc "cmd"` -- the shape every scripted probe takes -- is interactive with a pipe for stdout. Unguarded, `$(zsh -ilc "command -v claude")` returned six lines of banner ahead of the answer and took down an Ansible assertion that was parsing it. Any future top-level output needs the same guard.
- **`alias z` deliberately shadows zoxide's `z`, and that is a decision, not an oversight.** `zoxide init zsh` defines `z` as a function near the top of `.zshrc`; the zshrc-editor alias is declared further down and an alias beats a function at command position. The editor keeps the letter because it is the older muscle memory; zoxide stays usable through `zi`. Confirmed on a classroom seat 2026-09-11, where `whence -w z` reports `alias` and `whence -w zi` reports `function`. Anyone tempted to "fix" this should read the comment above the alias first.

## Ruled out

- **The emoji vocabulary** (`✅📦ℹ️⚠️❌`). It carried colors no script can override, `❌` renders a red the brand forbids, and its inconsistent advance widths are why the house style once had to document that "the uneven emoji padding is deliberate." The crest `⛩` survives in banners as brand furniture, not as a status marker.
- **Indenting subprocess output.** Piping `apt` or `curl` through `sed` to align it kills progress meters, swallows interactive sudo prompts, and buffers what should stream. Raw subprocess output stays flush left; only script-authored lines carry the gutter.
- **A per-line separator.** `printline` between every message meant nothing. A rule now marks a phase boundary, which is information.

## Gotchas

- **qol is public, so a home path in a tracked file is refused by the `no-private-paths` hook** (2026-10-28). Name student-setup or a vault note by name; a line that has to keep one, like the directory aliases, carries `public-path-ok`. One line is left unmarked on purpose: `install_zsh_starship.sh:1098` (`/Users/x`), because student-setup vendors that file byte for byte. Add the marker the next time the file changes and is re-vendored, or the hook blocks that commit. (cross-project)
- **`linux/docker_install.sh` cannot run under `bash <(curl …)`, and `install_zsh_starship.sh` can** (measured 2026-09-08 in `ubuntu:24.04`). docker_install derives `SCRIPT_DIR` from `dirname "$(realpath "$0")"`, and under process substitution `$0` is `/dev/fd/63`, which resolves to a pipe with no writable directory — the base_functions.sh self-heal then dies with `curl: (23) Failure writing output to destination` and the run stops before the banner. `curl … | bash` works (SCRIPT_DIR falls back to `.`) but litters the cwd and would break the two `read -r -p` prompts on the already-installed path, so the README documents `curl -o` then `sudo bash`. The Starship script uses `${BASH_SOURCE[0]}` and has no prompts of its own — only the theme block's unused `ask_*` helpers — so process substitution runs it clean end to end. **How to apply:** switching docker_install's SCRIPT_DIR to a writable fallback would make both scripts take the same one-liner; until then the README's two forms are deliberate, not sloppy.

- **`configs/tmux.conf` runs two plugins by absolute path that nothing here installs — measured 2026-08-21 on a factory Mac.** The last two lines `run ~/.config/tmux/plugins/catppuccin/tmux/catppuccin.tmux` and `run '~/.config/tmux/plugins/tpm/tpm'`, and on a machine where neither is present each is `returned 127` at every tmux start. tpm does not save this: its `tpm` script binds `prefix + I` to an installer and returns, so loading it installs nothing. Invisible on any machine that has installed them by hand, which is every machine this config has ever run on until now. Found by `student-setup`'s `verify` on a fresh MacBook (student-setup's `docs/working-notes.md`, 2026-08-21). **Change made here:** catppuccin is now declared alongside the other five as `set -g @plugin 'catppuccin/tmux'`, so `prefix + I` keeps it current — that is a declaration, not an install. **How to apply:** anything consuming this config still has to put tpm and catppuccin on disk itself; `student-setup`'s `editors` Module clones both before writing the file. A standalone qol user runs the two clones by hand, or the `run` lines want an `if-shell` existence guard so a bare machine gets a working tmux instead of two errors.

- **`_term_cols` needs both `2>/dev/null` *before* `</dev/tty` and a trailing `|| true`, and neither is style** (2026-08-20). With no controlling terminal — cron, CI, an agent, `ssh host cmd` — opening `/dev/tty` fails. Bash applies redirections left to right and reports a failed one on **its own** stderr, so the old `</dev/tty 2>/dev/null` printed `/dev/tty: Device not configured` past a suppression not yet in effect; the reorder silences that. **The reorder is not the fix.** The pipeline still exits non-zero, and a script running under `set -E` inherits its ERR trap into the command substitution and dies right there, at its opening banner, before doing anything. **Every script in this repo sets `-eo pipefail` and therefore only printed the message** — which is why this looked cosmetic for a week — but student-setup's `scripts/bootstrap.sh` sets `-Eeo` and reported `Failed at line 239` and stopped. One letter is the difference between noise and a script that cannot run unattended. `|| true` makes the fallback to 80 a fallback rather than a fatality; with a real terminal nothing changes, which `tests/test-term-width.sh` proves in the direction a no-tty test cannot see. Fixed in `linux/base_functions.sh` and byte-copied to all five embedding scripts here, plus student-setup's `scripts/vm.sh`, `scripts/bootstrap.sh` and its two vendored copies under `src/student_setup/payload/qol/`.
- **student-setup vendors two of this repo's scripts and no test on either side holds them together** (2026-08-20). `install_nano.sh` and `install_zsh_starship.sh` are copied into student-setup's `src/student_setup/payload/qol/`. `tests/test-theme-sync.sh` here and `tests/test_theme_sync.py` there both cover the *theme block* in those files, so a block change cannot drift — but the rest of either script can, silently. **How to apply:** when changing a qol script that student-setup vendors, re-copy it there in the same pass.

- **Unused color variables trip shellcheck SC2034.** This has bitten twice — `QOL_SEL` in `base_functions.sh` (commit `c680f18`) and two inks in the since-removed `gotime`. The rule that settled it: an SGR *attribute* with no reader gets deleted, a *token ink* with no reader gets a `# shellcheck disable=SC2034` and a comment saying why, because dropping a token from a palette copy makes it a worse copy.
- **A cache that stores rendered text cannot be themed** (2026-08-09). `netstatus.sh` cached its finished output line, so painting `_ns_render` would have written ANSI into `~/.cache/qol/netstatus` — and then a `NO_COLOR=1` shell would replay the escapes, while one piped run would poison the cache uncolored for every shell after it. The cache now holds the *state* (`online|portal|nodns|offline|none`) and the interface label on separate lines, and `_ns_paint` applies ink at print time. Migration needed no version field: the old format's line 2 was a rendered line, which can never match one of the five state tokens, so `_ns_cache_read` rejects it and re-probes. Generalize the rule — **cache the decision, not the rendering**; anything a caller's environment can change belongs on the print path.
- **`netstatus.sh` embeds the generated ink block, not a hand-written palette** (2026-08-09). It needs the colors and none of the badge grammar, and the obvious move — hand-writing five inks — would have made a copy the generator cannot check or rewrite. Instead it carries the same marker-bounded region the theme copies do, under the same `QOL_*` names, so `--check` and `--write-qol` reach it and `tests/test-theme-sync.sh` proves it matches. The cost is nine ink variables where six are read, suppressed with `# shellcheck disable=SC2034`. That is the standing rule: **a token ink with no reader is suppressed, not deleted** — dropping a color from a palette copy makes it a worse copy.
- **`ASSUME_YES` is a contract, not a convenience, and `ask_confirm` opts a script into it silently** (2026-08-09). `ask_confirm` returns yes whenever `ASSUME_YES` is set. That is right for `install_nano.sh` and `uninstall_omz_p10k.sh`, which both document a `--yes` flag. It is wrong for `linux/kernel_update.sh`, which has no flags: converting its `rpi-update` prompt to `ask_confirm` would have let a stray environment variable flash unreleased firmware to a Pi that the prompt exists specifically to protect. Before swapping a hand-rolled prompt for the helper, check whether the script actually publishes `--yes`. Where it does not, borrow the chrome and keep the `read` — `script-design.md` lists all four reasons an exception is legitimate.
- **`bash -n` does not catch a broken line continuation, and `shellcheck` does** (2026-08-09). Generating shell from a Python heredoc double-escaped the continuations, so `printf '%s\n' "line one" \` ended in a literal `\\` — a valid escaped-backslash argument — and the second line silently became its own command. Every affected script still parsed clean. `shellcheck -x` flagged it as SC2288 ("interpreted as a command name ending with '.'"). Prefer the Edit tool over generated shell for anything with continuations, and treat `shellcheck` as the real gate; `bash -n` only proves the file is *a* program, not the one you meant.
- **Never clear the screen at the top of a TUI redraw** (harvested → [[never-clear-the-screen-at-the-top-of-a-tui-redraw]])
- **Never put `2>/dev/null` on a `tput` you are capturing.** `cols="$(tput cols 2>/dev/null)"` reports the terminfo default of 80 no matter how wide the terminal is. ncurses reads the window size off whichever of stdout/stderr is a terminal; command substitution takes stdout, and the redirect throws stderr away, so it falls back to the static capability. `$(tput cols)` without the redirect answers correctly — the redirect *is* the bug. This pinned **every full-width element in the design system** to 80 columns for the life of the rebrand: `printline`, `banner`, `log_complete`, `log_phase`, and `ask_choice`'s selection bar (fixed 2026-08-08; `tests/test-term-width.sh` forces a 137-column pty and guards them). `_term_cols` now asks `stty size </dev/tty`, which no amount of nesting can hide, with `COLUMNS` as an explicit override and 80 as the floor. Reject a non-positive `COLUMNS` as well as a non-numeric one — this harness exports `COLUMNS=0`.
- **The symptom hid in plain sight for the whole rebrand.** Two menu screenshots taken at different window sizes both showed a rule of exactly 1759 px — an identical absolute width at two different window widths, which is what a hard-coded column count looks like. Nothing looks broken at a glance; the chrome is simply narrower than the window. Measure a rule against the window before believing it fits.
- **A selection bar is padded with spaces, never stretched with `CLR_EOL`.** `ESC[K` only paints the current background across the rest of the line on terminals with the `bce` capability. `xterm-256color`, `ghostty` and `linux` have it; **`screen`, `screen-256color` and `tmux-256color` do not**, and there `ESC[K` erases to the *default* background, cutting the bar off exactly where the text ended. `ask_choice` is called by installers, which routinely run under tmux over SSH, so `_ask_choice_draw` pads every row out to `_term_cols` instead (fixed 2026-08-08; `tests/test-theme.sh` asserts both the selected and unselected row equal the terminal width). Padding the *unselected* rows is half the fix — that is what paints over the bar as it moves away. Measure the pad against a template with the same leading width as the row actually prints: three columns, `" ❯ "` or three spaces, not four.
- **`QOL_COLOR_DEPTH` must be exported or prefixed, and the failure mode is silence.** A bare `QOL_COLOR_DEPTH=256` on its own line is a shell variable, not an environment variable, so a script run as a child process — even through an alias — never sees it and quietly renders truecolor. The screen looks *fine*, just not at the tier you asked for, so it reads as "the 256 tier is broken" rather than "the variable never arrived." Use `QOL_COLOR_DEPTH=256 ./script` on one line, or `export` it first. Two screenshots taken this way on 2026-08-08 came back pixel-identical, zero channel delta.
- **The repo-wide emoji grep now nearly passes, and the two survivors are deliberate** (updated 2026-08-09). The rebrand reached every remaining script, so `grep -rn '✅|📦|ℹ️|⚠️|❌'` over the shell scripts is clean *except* for `netstatus.sh`, whose `🛜 ✅ ❌ 🔒 🔌` are its product output rather than log badges — it prints a one-line readout at shell startup, and the nine-column badge grammar would destroy it — and the docs under `docs/`, which quote the retired vocabulary on purpose. Scope the check to exclude those two and it is silent.
- **`--write-qol` reaches only marker-bounded regions.** The vault rewrites the text between `# ‒‒ generated by dojobrain …` and `# ‒‒ end generated block`, and reports rather than guesses when a file lacks those markers. A file without them is invisible to the writer.
- **Starship's `command_timeout` is 2000, not the default 500, and the reason is the first run on a new Mac** (2026-09-10). A freshly set-up Mac prints a red `Executing command "/opt/homebrew/bin/python3" timed out` across the prompt on the first `cd`, then never again: the first execution of a just-installed Homebrew binary pays a cold start the next thousand do not, and 500ms does not cover it. Measured warm on this bench the same day, `python3 --version` answers in under 10ms, so the default is generous for every run except the one that matters. **It is not a Python problem** — six modules in the config run a command to find a version (`c`, `rust`, `golang`, `nodejs`, `java`, `python`) and any of them can be the one that goes first. Reported off a student-setup take-home run, where a scary warning on a brand-new machine is worst: it self-heals after one prompt, which is exactly what makes it hard to tell from a broken install. **How to apply:** the value lives in `configs/starship.toml` *and* in the heredoc inside `install_zsh_starship.sh`, which are byte-identical past the latter's six-line generated-file header and nothing tests that they are — change both, then re-copy the script into student-setup by the vendoring rule above.
- **The two theme-block copies must stay byte-identical.** `install_zsh_starship.sh` embeds a copy because it must run on macOS where `linux/base_functions.sh` is unavailable. `tests/test-theme-sync.sh` is the only thing keeping that copy honest — run it after touching either file.
- **The vault never runs git here.** A `--write-qol` run lands uncommitted on purpose; committing in this repo is always a human act.
